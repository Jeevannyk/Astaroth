ASTAROTH ARCHITECTURE: one process, one data file, append-only log + in-memory hash index
(plain text so it renders in any editor with Wi-Fi off; the same diagram is in ARCHITECTURE.md, Part 1)

=== COMPONENT MAP ======================================================================================  arrows: calls / data flow

  kvdb CLI ------+                       (cmd/kvdb/commands.go: open put get del batch dump check)
                 |
  kvdb serve ----+--> engine.DB  CLIENT API ----[L2 exclusive]----> WRITE PATH  (steps 1-9 below)
  (stdin/stdout) |     |       |                                         |
                 |     |       |                                         v
  torture -------+     |       |                                  DISK-FULL GUARD  (step 4)
  (drives serve as     |       |                                         |
   a child process,    |  [L2 shared]                                    v
   SIGKILLs it)        |       |                                  LOG WRITER + COMMIT MARKER  (steps 5-7)
                       |       v                                         |   EncodeFrame, WriteAt, Sync
                       |  IN-MEMORY INDEX  <------ index.Apply (step 8) --+
                       |  key -> file offset                             v
                       |       ^                                   +-----------------+
                       |       +----- index.Apply ---- RECOVERY <--| DATA FILE <path>|
                       |                               (Open: R1-R9)+-----------------+
                       |                                                  ^
                       +--> COMPACTION (K1-K8) ---> <path>.compact.tmp ---+ K6: atomic replace

  LOCKS  [L1] <path>.lock  OS file lock, one process per database (src/lock: CreateFile share mode 0 on Windows,
                           flock on Unix). Taken by Open (and by Check), released by Close, or by the OS when
                           the process dies, so a kill never leaves a stale lock.
         [L2] DB.mu        sync.RWMutex in engine.DB. Exclusive for the whole write path: Put, Delete, Batch,
                           Compact, Close. Shared: Get, Len, Dump. Writes are therefore serialized: at most one
                           frame is ever in flight, so a crash can tear at most the last frame of the file.

=== WRITE PATH  Put / Delete / Batch -> appendLocked (src/engine/engine.go) ==========================  L2 held from 2 to 9

   1  validate every op: key 1..1024 B, value <= 1 MiB, <= 10,000 ops     storage.ValidateOp    (nothing written on error)
   2  mu.Lock()                                                            DB.mu  [L2]
   3  auto-compaction if file >= 4 MiB and less than half is live          maybeAutoCompactLocked -> compaction K1-K8
   4  DISK-FULL GUARD: end + frame size <= limit ?                         ensureRoomLocked
        no:  compact first if that makes room, else ErrDiskFull, and no byte is written
        limit = MaxBytes - reserve for frames with a put; MaxBytes for delete-only frames
   5  LOG WRITER: encode ONE frame = header | records | COMMIT MARKER      storage.EncodeFrame
        the commit marker (frame_crc, CRC32C) is computed last, over the header and every record
   6  WriteAt(frame, end): one call, at the offset the engine owns         os.File.WriteAt  (pwrite / WriteFile)
        error: Truncate(end) rolls the partial frame back
   7  Sync(): fsync on Unix, FlushFileBuffers on Windows   <== DURABLE      os.File.Sync
        error: the handle refuses every later write (ErrFailed); a failed fsync is never retried
   8  index.Apply(all ops); end += frame size; nextSeq++                   index.Apply   (readers see none or all)
   9  mu.Unlock(); return nil   ->   serve writes "ACK <id>"               serve.reply   (an ACK is only written here)

=== IN-MEMORY INDEX (src/index) =======================================================================================
   map[key] -> { RecOff int64 (file offset of the PUT record), ValLen uint32 },  plus LiveBytes (size of live records)
   NOT persisted: rebuilt from the log on every Open.   Get: RLock -> index -> ReadAt(record) -> record key must match

=== DATA FILE <path>  (little-endian; beside it: <path>.lock, and <path>.compact.tmp only while compacting) ===========

   +-------------+-----------+-----------+-----+-----------+
   | header 32 B |  frame 1  |  frame 2  | ... |  frame N  |      a crash can leave only frame N incomplete (torn tail)
   +-------------+-----------+-----------+-----+-----------+

   HEADER (32 B)  off 0 magic "ASTAROTH" 8 | 8 version 4 (=1) | 12 flags 4 (=0) | 16 generation 8 | 24 header_crc 4 | 28 reserved 4
                  header_crc = CRC32C of bytes 0..23; generation = 1 at creation, +1 per compaction

   FRAME = one transaction = one Put, one Delete, or one whole Batch
   +---------------+---------------+----------------+-------------+--------------+-----------------+
   | frame_magic 4 | payload_len 4 | seq 8          | op_count 4  | payload N    | frame_crc 4     |
   | 0xA57A0F01    | N <= 64 MiB   | TRANSACTION ID | 1..10,000   | the records  | COMMIT MARKER   |
   +---------------+---------------+----------------+-------------+--------------+-----------------+
   off 0           4               8                16            20             20+N        total = 24 + N bytes
   frame_crc = CRC32C (Castagnoli) of bytes 0 .. 20+N-1, i.e. of the frame header and every record
   committed  <=>  magic ok  AND  24+N <= bytes left in the file  AND  frame_crc matches  AND  seq = previous seq + 1

   RECORD (inside the payload, back to back, applied in order: the last op on a key wins)
     PUT  type 1 (=0x01) | key_len 2 (1..1024) | val_len 4 (0..1,048,576) | key | value      7 + k + v bytes
     DEL  type 1 (=0x02) | key_len 2 (1..1024) | key                                       3 + k bytes (tombstone)

=== RECOVERY FLOW  engine.Open -> src/recovery =====================================  a kill anywhere here: rerun gives the same result

   R1  lock.Acquire(<path>.lock)                                held by another process -> ErrLocked
   R2  CleanupCompaction:  data file + tmp -> remove tmp  |  tmp, no data file -> rename tmp into place  |  else nothing
   R3  storage.OpenFile: create if missing; O_RDWR, never O_APPEND
   R4  file < 32 B ?  empty, zeros, or a prefix of our header -> WriteHeader + Sync (empty database)  |  else ErrNotOurFile
   R5  DecodeHeader: magic, header_crc, version                 bad -> ErrNotOurFile, file untouched
   R6  scanLog, frame by frame: magic, length fits, CRC, seq = prev+1, records parse  ->  index.Apply(frame)
         CRC-valid but malformed, or a seq gap -> ErrCorrupt, file untouched
   R7  the first invalid frame ends the log;  invalid bytes > one maximum frame -> ErrCorrupt, file untouched
   R8  invalid bytes > 0 -> Truncate(end) + Sync               removes the torn write; new frames go to `end`
   R9  ready: end, nextSeq, index

=== COMPACTION  Compact, or auto (step 3), or the disk-full guard (step 4) -> compactLocked (src/engine/compact.go) ==  L2 held

   K1  create <path>.compact.tmp (truncating a leftover)
   K2  write header (generation + 1), then only the live records: one sequential scan of the log; overwritten values and
       tombstones are dropped; frames of <= 1,000 records or 8 MiB; the temporary file may not exceed MaxBytes (else ErrDiskFull)
   K3  tmp.Sync()
   K4  verify: recovery.Recover(tmp) must give exactly the index built in K2      mismatch -> abort
   K5  close tmp; close the data file (Windows cannot replace an open file)
   K6  ReplaceFile(tmp -> path): MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH) on Windows, rename(2) on Unix  <== COMMIT POINT
   K7  SyncDir: fsync of the directory on Unix (Windows: WRITE_THROUGH in K6 already made the rename durable)
   K8  reopen the data file; switch to the new index, end and nextSeq
   failure before K6 -> remove tmp, old file untouched and authoritative   |   after K6 -> the new file is the data file
